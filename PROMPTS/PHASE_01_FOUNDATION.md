# Antigravity Prompt — Phase 1: Foundation

Read `README_FIRST.md`, `ANTIGRAVITY_RULES.md`, `PROJECT_CHARTER.md`, `TECHNICAL_ARCHITECTURE.md`, `ROADMAP_AND_TASKS.md`, and `PROJECT_STATE.md` before acting.

## Task
Build only the Phase 1 foundation for FIT SPACE. First inspect the current workspace and Git status. Do not overwrite existing work. If a project already exists, summarize its structure and adapt rather than creating duplicate frameworks or entry points. If the workspace is empty, create a React + TypeScript + Vite frontend.

## Product UI
Create a polished, responsive fashion-tech interface called FIT SPACE. Visual direction: premium, clean editorial fashion shopping; warm neutral background, strong typography, restrained accent colour, clear cards, generous whitespace. Avoid generic admin-dashboard appearance.

Build these screens/sections:
1. Landing/hero: clear value proposition and “Start virtual try-on” CTA.
2. Try-on workspace layout with:
   - garment image upload drop zone (Phase 1 may show a well-labelled preview-only demo; real upload validation is Phase 2)
   - sample garment cards,
   - avatar/measurement panel with clearly marked future capability if not implemented,
   - central preview panel,
   - right-side fit/style results panel with honest “Preview prototype / not yet a fit guarantee” messaging.
3. Header/navigation and footer/privacy note.
4. Responsive desktop, tablet, and mobile layouts.
5. Loading, empty, and error states where relevant.

## Constraints
- Do not implement AI inference, backend, accounts, database, real fit predictions, or actual cloth simulation in Phase 1.
- Do not use external product images unless their use and license are clear. Prefer CSS/locally-created placeholders or assets whose license can be documented.
- Do not display a button that falsely claims an unimplemented feature works. Disabled or labelled “Coming in a later phase” is acceptable.
- Keep components small and readable; avoid duplicate declarations/components.
- Use TypeScript properly; do not silence type errors with `any` unless justified.
- Add basic tests and scripts for lint/typecheck/build/test as appropriate to the chosen setup.
- Add or update the root README with exact setup and run commands.
- If using a UI generated by Google Stitch, review it for maintainability and accessibility before integrating. Stitch is for UI/design/code generation, not the backend.

## Acceptance criteria
- App installs and runs locally using documented commands.
- Landing page and try-on workspace render without console errors.
- Responsive layout works at desktop and mobile widths.
- Demo/sample content is clearly labelled and not misrepresented as AI output.
- Lint/typecheck/build/tests are run; report actual results.
- Update `PROJECT_STATE.md` and `ROADMAP_AND_TASKS.md` only for verified work.
- End with a report listing files changed, commands run, results, blockers, and exact next step.

Do not continue into Phase 2 until Phase 1 is reviewed.
